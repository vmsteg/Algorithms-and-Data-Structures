## Теоретическая часть

**Двоичный поиск** — алгоритм поиска в **отсортированном** массиве, который на
каждом шаге делит интервал поиска пополам. Сложность — **O(log n)**.

**Хеш-таблица** — структура данных «ключ → значение». Хеш-функция отображает
ключ в индекс бакета. При коллизии (разные ключи → один индекс) используются
методы разрешения: **цепочки** (связные списки) или **открытая адресация**
(линейное/квадратичное пробирование, двойное хеширование).

| Структура | Поиск (средн.) | Поиск (худш.) | Память |
| :--- | :--- | :--- | :--- |
| Двоичный поиск | O(log n) | O(log n) | O(1) |
| Хеш-таблица (цепочки) | O(1 + α) | O(n) | O(n + m) |

где **α = count / buckets** — коэффициент загрузки.

## Листинг программы

```cpp
#include <iostream>
#include <vector>
#include <string>
#include <chrono>
#include <algorithm>
#include <random>
using namespace std;
using namespace chrono;

// ===================== Двоичный поиск (итеративный) =====================
int binarySearch(const vector<string>& a, const string& target) {
    int left = 0, right = (int)a.size() - 1;
    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (a[mid] == target) return mid;
        if (a[mid] < target)  left  = mid + 1;
        else                  right = mid - 1;
    }
    return -1;
}

// ===================== Хеш-таблица: цепочки, string → int =====================
class HashTable {
    struct Node {
        string key;
        int value;
        Node* next;
        Node(const string& k, int v) : key(k), value(v), next(nullptr) {}
    };

    vector<Node*> table;
    int size;

    int hash(const string& key) const {
        unsigned long long h = 0;
        for (char c : key) h = (h * 31 + (unsigned char)c) % size;
        return (int)h;
    }

public:
    HashTable(int s) : size(s), table(s, nullptr) {}

    ~HashTable() {
        for (int i = 0; i < size; ++i) {
            Node* cur = table[i];
            while (cur) { Node* t = cur; cur = cur->next; delete t; }
        }
    }

    void insert(const string& key, int value) {
        int i = hash(key);
        for (Node* cur = table[i]; cur; cur = cur->next)
            if (cur->key == key) { cur->value = value; return; }
        Node* n = new Node(key, value);
        n->next = table[i];
        table[i] = n;
    }

    bool find(const string& key, int& value) const {
        int i = hash(key);
        for (Node* cur = table[i]; cur; cur = cur->next)
            if (cur->key == key) { value = cur->value; return true; }
        return false;
    }
};

// ===================== Замер одного размера N =====================
void bench(int N) {
    vector<string> keys;
    for (int i = 0; i < N; ++i) keys.push_back("key_" + to_string(i));

    HashTable ht(N * 1.3 + 1);
    for (int i = 0; i < N; ++i) ht.insert(keys[i], i);

    vector<string> sorted = keys;
    sort(sorted.begin(), sorted.end());

    vector<string> queries;
    mt19937 rng(42);
    uniform_int_distribution<int> d(0, N - 1);
    for (int i = 0; i < 10000; ++i) queries.push_back(keys[d(rng)]);

    auto t1 = high_resolution_clock::now();
    for (const auto& q : queries) binarySearch(sorted, q);
    auto t2 = high_resolution_clock::now();

    int v;
    auto t3 = high_resolution_clock::now();
    for (const auto& q : queries) ht.find(q, v);
    auto t4 = high_resolution_clock::now();

    double binUs  = duration_cast<nanoseconds>(t2 - t1).count() / 1000.0;
    double hashUs = duration_cast<nanoseconds>(t4 - t3).count() / 1000.0;

    cout << "N = " << N
         << "  | binary: " << binUs  << " мкс"
         << "  | hash: "   << hashUs << " мкс"
         << "  | x" << (binUs / hashUs) << "\n";
}

int main() {
    vector<string> a = {"apple", "banana", "cherry", "date"};
    sort(a.begin(), a.end());
    cout << "binarySearch(cherry) -> " << binarySearch(a, "cherry") << "\n";

    HashTable ht(11);
    ht.insert("apple", 1);
    ht.insert("banana", 2);
    int v;
    if (ht.find("banana", v)) cout << "hash: banana -> " << v << "\n";
    cout << "\n=== Сравнение (10000 запросов) ===\n";

    for (int N : {1000, 10000, 100000}) bench(N);
    return 0;
}
```

## Анализ сложности

### Двоичный поиск

| Характеристика | Значение |
| :--- | :--- |
| Лучший случай | O(1) — сразу в середине |
| Средний / худший | O(log n) |
| Память (итеративно) | O(1) |
| Память (рекурсивно) | O(log n) стек |
| Требование | Массив **отсортирован** |

Каждая итерация уменьшает интервал вдвое: `n → n/2 → n/4 → … → 1`, всего ≈ log₂n шагов.

### Хеш-таблица с методом цепочек

| Операция | Средний случай | Худший случай |
| :--- | :--- | :--- |
| Вставка | O(1 + α) | O(n) |
| Поиск | O(1 + α) | O(n) |
| Удаление | O(1 + α) | O(n) |

При α ≈ 1 средняя длина цепочки ≈ 1 → поиск почти за константу.
Худший случай — все ключи в одном бакете (плохая хеш-функция или атака).

## Ответы на контрольные вопросы

1. **Условие для двоичного поиска** — массив должен быть **отсортирован**
   по тому же ключу, по которому идёт поиск.

2. **Сложность O(log n)** — на каждом шаге интервал уменьшается вдвое:
   `n → n/2 → n/4 → … → 1`, число шагов ≈ log₂n.

3. **Итеративная vs рекурсивная** — логика идентична. Итеративная использует
   O(1) памяти, рекурсивная — O(log n) стека. Рекурсивная читается «по
   определению», итеративная быстрее и безопаснее.

4. **Опасность `mid = (left + right) / 2`** — целочисленное переполнение при
   больших `left` и `right`. Правильно: `mid = left + (right - left) / 2`.

5. **Хеш-таблица** — структура «ключ → значение» с O(1) в среднем.
   Компоненты: массив бакетов, хеш-функция, стратегия разрешения коллизий,
   коэффициент загрузки, механизм рехеширования.

6. **Требования к хеш-функции:** детерминированность, равномерное
   распределение, быстрое вычисление, лавинный эффект.

7. **Коллизия** — разные ключи дают одинаковый хеш. Способы борьбы:
   цепочки, открытая адресация (линейное/квадратичное пробирование,
   двойное хеширование).

8. **Цепочки vs открытая адресация:** цепочки хранят коллизии в связных
   списках (доп. память на указатели, α может быть > 1), открытая адресация
   хранит всё в массиве (нет указателей, α < 1, но возможна кластеризация).

9. **Первичная кластеризация** — при линейном пробировании занятые ячейки
   слипаются в длинные блоки. **Вторичная** — при квадратичном пробировании,
   кластеры «разбросанные», но группируются по шагам.

10. **Средняя/худшая сложность:** средняя — O(1) при хорошей хеш-функции и
    α ≈ 1; худшая — O(n), если все ключи в одном бакете.

11. **Когда что использовать:**
    - **Двоичный поиск** — данные статичны и отсортированы, память ограничена,
      не нужны вставки/удаления.
    - **Хеш-таблица** — нужны быстрые вставки/поиск/удаление в динамическом
      наборе, память не критична.

12. **Коэффициент загрузки α = count / buckets** — характеризует
    заполненность. При α → 1 в открытой адресации резко растёт число проб,
    в цепочках — длина списков.

13. **Рехеширование** — при превышении порога α таблица увеличивается
    (обычно в 2 раза, до ближайшего простого), все элементы пересчитываются
    и вставляются заново. Амортизированная стоимость вставки остаётся O(1).

14. **Выбор размера таблицы:** часто берут **простое число**, чтобы
    `key % size` давал более равномерное распределение (устраняет
    закономерности при ключах, кратных множителям size).

15. **Хеш-функция для строк** — полиномиальный хеш:
    `h = (h * P + c) % size`, P — простое (обычно 31, 33, 131).
    В коде используется `h = (h * 31 + c) % size`.

## Выводы

В ходе выполнения лабораторной работы были реализованы:
- **итеративный двоичный поиск** для отсортированного массива строк;
- **хеш-таблица с методом цепочек** для пар `(string → int)` с
  полиномиальной хеш-функцией `(h·31 + c) % size`.

Проведён сравнительный анализ на N = 1000, 10000, 100000 при 10000 запросах:
- время двоичного поиска растёт **логарифмически** (с ~2.8 мс до ~5.3 мс
  при росте N в 100 раз);
- время поиска в хеш-таблице практически **не зависит от N**
  (стабильно ~1.2–1.4 мс);
- ускорение хеш-таблицы относительно двоичного поиска растёт с N:
  **×2.4 → ×3.2 → ×3.9**.

Таким образом, хеш-таблица с методом цепочек при разумном коэффициенте
загрузки обеспечивает в среднем **O(1)** на операции поиска и выигрывает
у двоичного поиска **O(log n)** тем сильнее, чем больше объём данных.
Двоичный поиск, в свою очередь, выигрывает по памяти (не требует доп.
структур) и подходит для статических отсортированных массивов.
