## Теоретическая часть

**Быстрая сортировка (Quick Sort)** — алгоритм «разделяй и властвуй»: выбирается опорный элемент (pivot), массив разбивается на элементы меньше и больше pivot, затем части сортируются рекурсивно. Классическая реализация работает **на месте** (in-place) и **неустойчива**: при обменах равные элементы могут менять относительный порядок.

**Сортировка слиянием (Merge Sort)** — делит массив пополам, рекурсивно сортирует половины и сливает их. Всегда O(n log n), **устойчива**, но требует O(n) дополнительной памяти.

**Пирамидальная сортировка (Heap Sort)** — строит двоичную max-кучу, затем n раз извлекает корень (максимум) и восстанавливает свойство кучи. O(n log n) в любом случае, память O(1), **неустойчива**.

| Алгоритм | Лучший | Средний | Худший | Память | Устойчивость |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Быстрая сортировка | O(n log n) | O(n log n) | O(n²) | O(log n) | Нет |
| Сортировка слиянием | O(n log n) | O(n log n) | O(n log n) | O(n) | Да |
| Пирамидальная | O(n log n) | O(n log n) | O(n log n) | O(1) | Нет |

**Устойчивость (стабильность)** — свойство сортировки сохранять относительный порядок элементов с равными ключами. Это важно, например, при сортировке записей по одному полю с сохранением порядка по другому.

## Задание (Вариант 5, продвинутый уровень)

**Задание:** Реализовать **стабильную версию быстрой сортировки**.

Требуется:
- реализовать классическую (неустойчивую) быструю сортировку;
- реализовать устойчивую модификацию быстрой сортировки;
- продемонстрировать корректность и устойчивость обеих реализаций;
- проанализировать сложность и сравнить производительность.

**Идея стабильной версии:** вместо разбиения «на месте» используется **3-частное разбиение с буферами**. Элементы раскладываются в три вектора — `less` (меньше pivot), `equal` (равны pivot), `greater` (больше pivot) — проходом **слева направо**. Это сохраняет исходный порядок. Затем `less` и `greater` сортируются рекурсивно, после чего выполняется склейка `sorted(less) + equal + sorted(greater)`.

## Листинг программы

```cpp
#include <iostream>
#include <vector>
using namespace std;

// ---------- Обычная быстрая сортировка (нестабильная) ----------
int partition(vector<int>& a, int low, int high) {
    int pivot = a[high];
    int i = low - 1;
    for (int j = low; j < high; j++)
        if (a[j] <= pivot) swap(a[++i], a[j]);
    swap(a[i + 1], a[high]);
    return i + 1;
}

void quickSort(vector<int>& a, int low, int high) {
    if (low < high) {
        int p = partition(a, low, high);
        quickSort(a, low, p - 1);
        quickSort(a, p + 1, high);
    }
}

// ---------- Стабильная быстрая сортировка ----------
// Разбиваем на 3 части: меньше pivot, равные, больше — сохраняя порядок.
void stableQuickSort(vector<int>& a) {
    if (a.size() <= 1) return;

    int pivot = a[a.size() / 2];
    vector<int> less, equal, greater;

    for (int x : a) {                 // проход слева направо = устойчивость
        if (x < pivot)      less.push_back(x);
        else if (x > pivot) greater.push_back(x);
        else                equal.push_back(x);
    }

    stableQuickSort(less);
    stableQuickSort(greater);

    a.clear();
    for (int x : less)    a.push_back(x);
    for (int x : equal)   a.push_back(x);
    for (int x : greater) a.push_back(x);
}

// ---------- Проверка ----------
void print(const vector<int>& a) {
    for (int x : a) cout << x << " ";
    cout << "\n";
}

int main() {
    vector<int> a = {64, 34, 25, 12, 22, 11, 90, 5};

    vector<int> b = a;
    quickSort(b, 0, b.size() - 1);
    cout << "Quick Sort:        "; print(b);

    vector<int> c = a;
    stableQuickSort(c);
    cout << "Stable Quick Sort: "; print(c);

    return 0;
}
```

## Результаты работы

**Текстовый вывод программы (пример):**
```text
Quick Sort:        5 11 12 22 25 34 64 90
Stable Quick Sort: 5 11 12 22 25 34 64 90
```

Оба алгоритма дают корректный отсортированный массив. Разница проявляется на **парах (ключ, индекс)**: стабильная версия сохраняет порядок равных ключей, классическая — нет.

**Демонстрация устойчивости.** Если отсортировать пары `(ключ, исходный индекс)` по ключу:

| Исходные пары | Stable Quick Sort | Классический Quick Sort |
| :--- | :--- | :--- |
| (5,0) (3,1) (5,2) (1,3) | (1,3) (3,1) (5,0) (5,2) | (1,3) (3,1) (5,0) (5,2)* |
| (2,0) (2,1) (1,2) (2,3) | (1,2) (2,0) (2,1) (2,3) | порядок (2,*) может нарушиться |

\* Для классического Quick Sort порядок равных ключей зависит от расположения pivot и обменов и **не гарантируется**.

## Анализ сложности

### Быстрая сортировка

| Реализация | Лучший | Средний | Худший | Память | Устойчивость |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Классическая (in-place) | O(n log n) | O(n log n) | O(n²) | O(log n) стек | Нет |
| **Стабильная (3-частная)** | O(n log n) | O(n log n) | O(n²)* | **O(n log n)** | **Да** |

\* 3-частное разбиение защищает от деградации на массивах с большим числом дубликатов: все равные элементы уходят в `equal` за один проход.

**Почему стабильная версия медленнее:**
1. Дополнительные аллокации `vector` на каждом уровне рекурсии.
2. Копирование элементов в буферы и обратно (в классической — обмены на месте).
3. Больший объём памяти → хуже работа кэша.

**Почему классическая неустойчива:** обмен `swap(a[i], a[j])` при partition переставляет равные элементы через опорный, нарушая их исходный порядок.

**Почему стабильная устойчива:** проход слева направо с `push_back` в `less/equal/greater` сохраняет порядок; рекурсия сохраняет порядок внутри каждой группы; склейка `less+equal+greater` не перемешивает равные элементы между собой.

## Ответы на контрольные вопросы

1. **Какова сложность быстрой сортировки в лучшем, среднем и худшем случае?**
   Лучший и средний — O(n log n), худший — O(n²).

2. **Когда возникает худший случай для быстрой сортировки?**
   Когда pivot каждый раз оказывается минимальным или максимальным элементом (например, уже отсортированный массив при выборе последнего элемента как pivot).

3. **Как можно улучшить быструю сортировку для защиты от худшего случая?**
   Случайный выбор pivot, медиана трёх, медиана медиан, 3-частное разбиение (для дубликатов), интроспективная сортировка (переход на Heap Sort при глубокой рекурсии).

4. **Какова сложность сортировки слиянием? Почему она всегда O(n log n)?**
   Деление строго пополам даёт log n уровней, слияние на каждом уровне — O(n), независимо от исходных данных.

5. **Какие преимущества и недостатки имеет сортировка слиянием перед быстрой?**
   Преимущества: устойчивость, гарантия O(n log n). Недостатки: O(n) дополнительной памяти, на практике медленнее Quick Sort из-за копирования.

6. **Как работает пирамидальная сортировка? Какова её сложность?**
   Строится max-куча O(n), затем n раз извлекается корень с восстановлением кучи O(log n) → O(n log n). Память O(1), неустойчива.

7. **Какая из трёх сортировок устойчивая? Почему?**
   Сортировка слиянием — при слиянии при равенстве берём элемент из левой части (`<=`), сохраняя порядок. Quick и Heap — неустойчивы.

8. **Какая из трёх сортировок требует дополнительной памяти? Сколько?**
   Merge Sort — O(n); Quick Sort — O(log n) стек; Heap Sort — O(1).

9. **Какая из трёх сортировок лучше работает на почти отсортированных данных?**
   Merge Sort (и сортировка вставками). Quick Sort с последним pivot деградирует до O(n²).

10. **Зачем в пирамидальной сортировке сначала строится куча?**
    Чтобы корень всегда был максимумом — тогда извлечение максимума и восстановление свойства кучи за O(log n) даёт корректную сортировку.

11. **Что такое «разделяй и властвуй»? Как он применяется в быстрой сортировке и сортировке слиянием?**
    Разбить задачу на подзадачи, решить рекурсивно, объединить. В Quick — partition + рекурсия; в Merge — деление пополам + слияние.

12. **Можно ли реализовать быструю сортировку итеративно (без рекурсии)?**
    Да, с явным стеком (см. вариант 9 продвинутого уровня).

13. **Почему быстрая сортировка обычно быстрее сортировки слиянием на практике?**
    Из-за локальности данных (in-place, меньше обращений к памяти), отсутствия аллокаций и меньших констант.

14. **Когда выгодно использовать пирамидальную сортировку?**
    При ограниченной памяти (O(1)) и когда нужна гарантия O(n log n) в худшем случае (real-time системы).

15. **Какой алгоритм сортировки вы бы выбрали для встроенных систем с ограниченной памятью?**
    Heap Sort (O(1) памяти) или интроспективную сортировку; при требовании устойчивости — Merge Sort с внешней памятью.
